# Devlog: week 1 (12–20 October 2026)

The first week was about foundations. There is no inventory yet, but everything that makes inventory safe to build is in place: a working stack, a domain model written down before the code, two bounded contexts with real persistence, an API that fails in a consistent and translated way, and tenant isolation that does not depend on a developer remembering a `WHERE`.

## What shipped

| Area | Result |
|---|---|
| Stack | Docker Compose with FrankenPHP, PostgreSQL 17 and Redis; `make` for everything; five CI jobs on GitHub Actions |
| Quality | PHPStan at max level with strict rules, PHP-CS-Fixer, Rector, PHPat architecture rules running inside PHPStan |
| Domain | Ubiquitous language, event storming, aggregates with invariant IDs, context map (`docs/domain/`) |
| Warehouse and Catalog | Aggregates, value objects, Doctrine XML mappings, migrations, API Platform DTO resources |
| Errors | One `application/problem+json` shape, stable error codes, Spanish and English texts in ICU, a test that fails when a code has no translation |
| Identity | Tenants and users, JWT (RS256), roles `admin > supervisor > operator`, tenant taken from the signed-in user, a Doctrine SQL filter that fails closed |
| Demo data | `make demo` loads a fashion company (Marea Moda): 3 users, a distribution centre with 6 zones and 42 locations, 39 products in sizes and colours |

Nine pull requests were merged, and `main` is protected: nothing lands without the five checks green.

## Decisions worth remembering

- **Contexts meet only through `Application/Contract`**, and the allowed direction is a map in `ArchitectureTest`. Breaking it fails `make stan`, not a code review ([ADR 0003](../adr/0003-cross-context-communication-through-published-contracts.md)).
- **Domain errors carry a code, never a sentence.** The API translates them from `Accept-Language`, Spanish by default ([ADR 0004](../adr/0004-bilingual-interface-spanish-by-default.md), [ADR 0007](../adr/0007-one-translated-problem-shape-for-every-api-error.md)).
- **The tenant never comes from the request.** The first version took an `X-Tenant-Id` header, which was fine for a skeleton and wrong for anything else. It was removed when authentication arrived ([ADR 0008](../adr/0008-jwt-authentication-and-tenancy-from-the-signed-in-user.md)).
- **Two walls for tenancy**: use cases check the tenant, and a SQL filter adds it to every query. A missing tenant is an error, never "all tenants".
- **A demo from the author's own field.** Fashion has variants (size, colour) and no lots or expiry dates, which makes it a good first test of the model and a reason to keep tracking policy per product.

## What went wrong, and what it taught

- **A test suite that took 12 minutes.** Rebuilding the schema for every test and booting the kernel for every request were the cost. Building the schema once and truncating between tests, and keeping the kernel booted, brought 371 tests down to about 5 minutes.
- **Speeding it up exposed a real bug.** With the kernel no longer rebooted, the tenant filter of one request leaked into the next. Slow tests had been hiding it. It is fixed by resetting the filter at the start of every request, with a test for it.
- **Scripted edits corrupted files** (a `\a` became a control character, backslashes collapsed). The fix was to stop editing code through string escapes and to scan for control characters.
- **The CI failed on a missing executable bit** because Git on Windows does not keep it. The workflow now calls `php bin/console` and never relies on the bit.
- **`composer validate --strict`** rejected unbound `api-platform/symfony`; the constraint is pinned now and `make validate` runs it locally.
